# Design Thinking Module 4 : Prototype

**Innovation Challenge:** How to fix software vulnerabilities more productively, with less human intervention ?

Context: Automated tools handle vulnerability detection, but fixing and verifying them still requires human labor. Although organizations deploy full teams to manage security updates, rapid advancements in AI are surfacing flaws faster than ever—straining a remediation pipeline still bound by manual human pace.

**POV ( Point Of View ):** Eva, an experienced engineer eager to build user-facing products, NEEDS a way to eliminate low-value administrative friction (like slow approval chains and routine CVE fixes) so she can consistently ship meaningful releases, BECAUSE she's an overqualified, proactive value-builder whose time is being wasted on passive, repetitive process work that neither advances her career nor makes efficient use of a skilled (and well-compensated) resource for the company.

**HMW ( How might we ? ):** How might we fix cyber vulnerabilities with less human intervention, so engineers can focus on meaningful, high cognitive work?

*Public source material from [Design Thinkingl — Prototyping](https://web.stanford.edu/group/instr_design/cgi-bin/LEAD_TIP/dt_to_go/prototyping/index.html)*

## GitHub

Rather than a wireframe mockup, I built this real-world project as the interactive prototype.

The [pull requests section](https://github.com/raychenon/Design-Thinking-Prototype/pulls) contains PRs awaiting human validation.

- The only pull request created by a human is tagged with the yellow **`manual-fix`** label.
- All other pull requests were created by non-human agents.
- Human accountability remains a required part of the verification process.
